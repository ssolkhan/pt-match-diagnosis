What this tool does

PyroTech Match Diagnostics turns robot Driver Station logs into a dashboard that shows what happened in a match and what to check next. Open it at pt-match-dx.vercel.app.

It reads two files from each match: .dslog (telemetry such as battery, CAN and power) and .dsevents (messages and errors). You need both files from the same match. Versions 3 and 4 of the log format are supported.

Quick start

You can go from log files to a to-do list for the pit in five steps.

  1. Open the app and load a match, either by uploading both log files or by using Browse Timber Logs on GitHub.
  2. Enter the Battery ID and Event Name. Both are optional, but Match History is far more useful with them.
  3. Click Analyze Match.
  4. Read Match Summary for the health score and any red alerts.
  5. Open Insights and work through Fix Before Next Match from the top.

Loading a match

Use your own files when you have them on the laptop, and GitHub when the logs are already in the team's Timber repo.

The Driver Station laptop creates the log files, normally in C:\Users\Public\Documents\FRC\Log Files. The two files in a pair share the same date-and-time name.

From your computer

  1. Drag both the .dslog and .dsevents files onto the page, or click Upload Log Files and select both.
  2. If you add only one, the app tells you which file is still missing. Make sure the pair comes from the same match.
  3. When both show a green check, fill in the optional fields (your last Event Name is filled in for you) and click Analyze Match.

From GitHub

  1. Click Browse Timber Logs on GitHub.
  2. Pick a Folder. Folders can be months such as 03, or events such as States. The number in brackets is how many complete log pairs it holds.
  3. Pick a Match Pair. Pairs are named by the date and time of the log, so use the match time to find yours.
  4. Click Load & Analyze GitHub Match. This only downloads the logs. The Event Name fills in from the folder name, so correct it if the folder is a month such as 03.
  5. Add the Battery ID if you know it, then click Analyze Match.

Before analyzing, choose a Robot Power Profile for the robot that produced the logs. Choose Timber 2026 for that robot, Import CSV to add another robot, or No profile to see channel numbers and CAN IDs. The browser remembers your imported profiles and your last selection. The active profile appears at the top of the results.

Use CSV columns channel,can_id,description. Leave can_id blank or enter 99 for channels with no CAN ID. Add a group column to enable subsystem filters and identify motor channels for current anomaly checks. Use Sensors or Power for those channels.

To look at another match or use a different profile, click Load Different Logs at the top right.

The six tabs

The dashboard has six tabs. Start with Match Summary, and go to Insights when you want the to-do list.

Match Summary

This is the one-page overview of the match, and it opens first.

  • Match Health Score: a score out of 100 with a Score breakdown of what was deducted.
  • Alerts: CAN problems and motor anomalies appear here if any were found.
  • Match Mode Timeline: a colored bar showing time in Auto, Teleop, Disabled and Disconnected.
  • Stat cards: ten headline numbers, including Min Voltage, Peak Packet Loss, Peak CAN Usage, Brownouts and Critical Errors. Auto should be about 15 s and teleop about 135 s.

Unified Timeline

This tab shows what happened second by second, so you can see when a problem started and what else changed at that moment.

  • Main chart: Voltage and Packet Loss are on by default. You can also turn on CAN Usage, roboRIO CPU and Trip Time.
  • Mode strip: a smaller chart below shows the robot's mode over the same period.
  • Tooltips: hover over the chart to read values and see events logged close to that moment.

Power

This tab shows where the electrical current went, channel by channel.

  • Anomaly alerts: motors behaving unlike their partners, with Isolate on Chart.
  • Top Current Consumers: the three channels with the highest peak current.
  • Channel Visibility and chart: current over time for the channels you pick, grouped by mechanism such as Drivetrain, Intake and Shooter.
  • Channel table: Peak, Avg and Energy for each channel, with its CAN ID, group and status. Flagged channels are highlighted.

Errors & Warnings

This tab lists the messages the robot logged, cleaned up so repeats are grouped and routine noise is hidden. It shows what happened, so go to Insights for what to do about it.

  • Banners: CAN and motor anomaly summaries sit at the top.
  • Filters: show Critical, Warning or Info messages, and sort by severity or time.
  • Message list: click a row for the full text, or Seek to see that moment on the timeline.

Insights

This tab turns everything above into a prioritized to-do list. Each card says what is wrong, what to do next and what evidence supports it. See Reading the results for how the cards are grouped.

Match History

This tab compares matches over time, using every match saved to the team's sheet. It has a sortable table of saved matches and a battery trend chart below it. It needs an internet connection. See Saving and Match History for details.

Tab controls worth knowing

  • Show on Timeline and Seek jump to the Unified Timeline, zoomed to 5 seconds either side of that moment.
  • Match Only, Auto, Teleop and Full Log set the chart range on Unified Timeline and Power. Fullscreen enlarges the chart.
  • Channel Visibility on Power picks what is charted: All, None, Active Only, a mechanism group, or single channels.
  • Show Noise on Errors & Warnings reveals routine messages that are hidden by default.
  • Sort and filter chips on Errors & Warnings switch between severity and time order. A label like ×12 means the same message repeated 12 times.
  • Charts show two times: seconds since the log started, and match time, where the start of auto is 0:00. Error rows use seconds since the log started.

Reading the results

The health score tells you how bad the match was, and Insights tells you what to do about it.

Match Health Score

Every match starts at 100 and loses points for each problem found. Open Score breakdown to see exactly what was deducted. A log with no auto or teleop data is forced to 5, which usually means the robot never connected to the field. Logs from pit or idle sessions score 5 the same way.

Insights cards

Insights groups findings by urgency and puts the most serious first. Each card explains the problem, gives a next step after the arrow, and shows the evidence at the bottom.

  • Fix Before Next Match (red): act now, for example radio reboots, code exceptions or CAN timeouts.
  • Investigate When Possible (yellow): look into it when there is time, for example voltage sag or firmware warnings.
  • Systems Healthy (green): checks that passed.

The app also removes duplicate symptoms. A radio reboot card replaces the separate comms instability card, for example, so you see the cause and not every side effect.

Motor anomalies

The app compares motors that do the same job, such as the four swerve drive motors, and flags any that look different. A motor drawing far more than its partners can point to binding or a mechanical fault. One drawing far less can point to a bad connection or a motor that is not doing its share.

These alerts appear on Match Summary, Power and Errors & Warnings. Isolate on Chart opens that motor on the Power chart.

Saving and Match History

When you are online, every analysis saves automatically to the team's shared Google Sheet, so there is no save button. Everyone using the site sees the same history.

  • Save status: the header shows Saving..., then Save sent. Save sent means the request went out, not that the sheet confirmed it. If it matters, check that the row appears in Match History.
  • Duplicates: the app sends a new save each time you analyze, so analyzing the same match twice may add a second row.
  • Corrections: Battery ID and Event Name can't be edited in the app after a match is saved, so enter them carefully.

The Match History tab loads fresh each time you open it.

  • Filter: use All Events and All Batteries at the top of the table.
  • Sort: click any column heading, and click again to reverse the order.
  • Spot problems: values past their warning limit appear in red. Scroll sideways to see every column.

Battery Trending Across Matches sits below the table and needs at least 2 saved matches. It charts Min Voltage, Avg Voltage, Health Score or Resistance for each battery, match by match. Matches with no Battery ID are grouped as Unknown, which is why the Battery ID is worth entering.

Using it without WiFi

All the analysis runs in your browser, so you can diagnose a match in the pit with no internet. You only lose the features that need the cloud.

Set up before the event: on the project's GitHub page, choose Code, then Download ZIP, and unzip it on the laptop. Keep index.html and the vendor folder together with guide.html, because the charts and this guide load from there. To run it, open index.html in a browser.

Matches analyzed offline are not saved or queued. To add one to the history, analyze the same log files again on the live site once you are back online.

Terms

These are the terms you will see most often in the app.

TermWhat it means
AutoThe opening period of a match, when the robot runs on its own
BrownoutBattery voltage fell so low that the roboRIO cut motor output to protect itself. The app counts separate incidents and shows their total time. Older Match History rows may hold counts of 20 ms log samples instead, so they can look much higher
CANThe wiring network that connects motor controllers and sensors to the roboRIO
CAN stale dataA device's data was out of date, which can mean an intermittent connection
CAN timeoutA device on the CAN network stopped responding
Driver StationThe laptop software that controls the robot and creates the log files
FMSThe Field Management System that runs official matches
Loop overrunThe robot code took longer than its normal 20 ms cycle
Packet lossThe share of messages lost between the Driver Station and the robot
PDH or PDPThe power board that feeds each motor and device through its own numbered channel
roboRIOThe robot's main controller, which runs the team's code
TeleopThe part of a match when drivers control the robot
TimberThe GitHub repo where the team's match logs are stored
Trip timeHow long messages take to travel between the Driver Station and the robot
